# 系统设置:存库、展示类匿名可读、仅管理员会话可写

管理员需要在不重启、不重建镜像的前提下调整全实例的展示信息与界面默认值(标题、标志、默认主题、台账默认口径等),而仓库既有的配置通道是环境变量(改一次要重新部署)。我们决定:系统设置入库(标量存单例 JSON,标志字节另表),经 HTTP 接口读写——**读接口匿名开放**(登录页在认证前就要渲染标题与标志),**写接口仅限 ADMIN 登录会话、拒绝一切 Bearer 凭证**(含 attended),与用户管理/凭证管理同款红线;接口边界是只放展示类设置,敏感配置不得进入。

## Considered Options

- **环境变量 / 构建期注入**:符合既有 `env.ts` 传统,但每次调整都要改 `.env.production` 并重启容器,标志还要重新构建镜像;也不留审计。
- **标志写入 `public/` 目录**:容器文件系统不持久、standalone 产物在构建期固定,运行期落盘的文件随重新部署丢失;入库与附件子系统同模式。
- **读接口要求登录**:登录页在未认证时就要显示标题、标志与默认主题,读接口必须匿名;代价是该接口暴露的内容天然公开,故以「只放展示类设置」为硬边界。
- **写接口放行 attended 凭证**:登录页的文案与标志由设置驱动——被提示词注入的 agent 若能改它,就能伪造登录页外观(钓鱼);系统设置没有无人值守的场景,一刀切最简单。

## Consequences

- 新增设置项时必须先问「匿名可见是否无害」:敏感配置(密钥、策略阈值、内部地址)不得放进该接口,必要时另开需鉴权的接口。
- 设置属于实例级数据:进快照备份(全库),不进迁移包(单项目)。
- 修改留审计(前后值;标志只记类型与大小,不记字节)。
