## 业务契约

- 金额使用Decimal；PAID/应付未付、作废排除、一般/包干预算及年度/总口径保持。原有 `voidOnly` 合计覆盖筛选条件的问题改为条件交集，新增作废合计为零的回归。
- SSO/凭证逐请求授权，浏览器只合并尚未完成的相同GET；写后清除在途合并表。角色、停用、撤销和项目scope不跨请求缓存。
- 无编号指纹查重将金额/日期候选下推到数据库，各集合最多500个值；超过或格式不规范时按字段回退，最终摘要归一化指纹仍在服务端比较。真实PG回归中候选从103条降至1条。已有编号记录仍可被无编号新行命中。
- 查重与部分唯一索引继续兜底；批量新增不跳过冲突、不拆事务。补全更新继续逐行重验金额、只推进状态，并保留历史与审计。
- 两页录入时间口径分别是项目页 `enteredAt`、全局页 `createdAt`；筛选、排序、显示和导出一致。
- Excel固定成员及顺序，后续新增不混入。统计执行金额按捕获ID求和；删除时409。字段分批实时读取，严格同一快照需要另行设计。
- ZIP最多读取501条元数据作数量哨兵，通过数量/字节门后仅读捕获ID；排队期间新增不混入，删除或筛选关联变更409。既有应用不原地修改上传内容与大小。
- 大ZIP二进制读取按元数据大小分段，合计不超过8MiB；单个更大文件独占一段。每段等40ms日常API安静窗口，最多让行1秒后推进；请求在finally中释放计数，导入/导出不计入日常流量。此等待不能抢占已开始的读取，预算按段计算。
- 小文件即时执行。大文件预算跨路由共享，失败释放名额，超时明确反馈；完成下载才算文件可用。

## 测量校准与适用范围

初始基线与后期运行使用了不同Chromium版本，另补同一浏览器、同一稳定数据集的前后对照。初始十万条只读基线单独保留；写入负载逐步增加合成数据，每份结果记录实际起始行数。

驱动末端轮询可能额外等数百毫秒。同批100次操作对照后，主指标改为浏览器内真实点击至“本次写入及刷新成功、总数/唯一新摘要显示、弹窗完全卸载、无忙状态和骨架、两帧绘制”的时刻；保留 `observedMs`、`driverMs` 和分段值。缺失终点/超时判失败。该校准不算应用优化收益。

进程内队列适用于当前单进程运行，横向多实例需共享预算。Excel仍保留ID清单和压缩文件，ZIP仍按现有限额物化二进制；RSS含V8保留堆和缓冲区，不能称常量内存。实际载荷、样本及未覆盖的部署条件见结果报告。
